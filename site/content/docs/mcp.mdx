Skills are instructions for AI agents that you keep in a vault, and MCP lets agents on your computer use them, along with everything else in better-vault.

## Skills

A skill is a Markdown file in the `SKILL.md` format: a name, a description that says when to use it, and the instructions. Open **Skills** in the sidebar of the notebooks page to write one, or import `SKILL.md` files you already have. Each skill shows who changed it last: you, or the agent that edited it.

To use skills in a chat, open the prompt's **+** menu, choose **Skills** and tick the ones you want. Their instructions go with each question in that chat.

## Get skills from skills.sh

[skills.sh](https://skills.sh) lists skills that people share on GitHub, each with an `npx skills add …` command. To add them to your vault, press **+** on the Skills page and open the **Fetch** tab. Paste the command, a skills.sh link or a GitHub link, and press **Find skills**.

The dialog lists every skill it finds in that repository, the same ones the skills command would install. Tick the ones you want and press **Import**. Only each skill's `SKILL.md` is imported; other files in its folder, such as scripts, are left out.

## Connect an agent with MCP

The desktop app runs a [Model Context Protocol](https://modelcontextprotocol.io) server on your computer, so agents can use your notebooks, sources, notes, skills, calendar, chats, Studio outputs, bots and plugins. It is off until you turn it on, it listens only on your computer, and every request needs a token. Your settings and API keys are never shared.

<Steps>

### Turn it on

Open **Settings → MCP** in the desktop app and turn on **Allow agents to connect**. Agents can always read; under **What agents may change**, each part has its own switch, and **Read only** turns every change off. Plugins stay off until you allow them.

### Set up your agent

Pick your agent, Claude Code, Cursor, Codex or Claude Desktop, and copy the setup shown. For Claude Code it is one command to run in a terminal.

### Use it

Ask your agent about your notebooks. It starts with `describe_app`, which tells it what each part holds and what it may change, then uses the tools below. Changes show up in the app at once.

</Steps>

## What agents can do

| Part          | Read                                                                                     | Change (when allowed)                                                                  |
| ------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **Notebooks** | `list_vaults`, `list_folders`, `list_notebooks`, `list_files`, `read_file`               | `create_notebook`, `rename_notebook`                                                   |
| **Sources**   | `search_sources`, `read_source`                                                          | `add_source` (text, a link or a YouTube video), `set_source_selected`, `delete_source` |
| **Notes**     | `list_notes`, `search_notes`, `read_note`, `list_backlinks`                              | `write_note`, `delete_note`                                                            |
| **Skills**    | `list_skills`, `read_skill`, and each skill as a prompt                                  | `write_skill`, `delete_skill`                                                          |
| **Calendar**  | `list_events`                                                                            | `create_event`, `update_event`, `delete_event`                                         |
| **Activity**  | `list_chats`, `read_chat`, `list_outputs`, `read_output`, `list_bots`, `read_bot_thread` | —                                                                                      |
| **Plugins**   | `list_plugins`, `read_plugin`                                                            | `install_plugin`, `update_plugin`, `remove_plugin`                                     |

Notes, sources and skills are also resources, at `note://`, `source://` and `skill://` addresses. [Creator mode](/docs/creator-mode) explains how an agent builds plugins.

The web app can't run an MCP server, so Settings → MCP there links to the desktop app. **New token** in the same page stops every agent set up with the old one.

## Vault script (beta)

Vault script lets an agent write one short JavaScript program that calls the tools above, instead of calling them one at a time. The agent combines and filters the results in code and sends back only what it needs, so a task that took ten tool calls takes one, and uses far fewer tokens.

Turn on **Allow Vault script** in Settings → MCP. Agents then get two more tools: `vault_api`, which lists the tools a script can call with their inputs, and `run_vault_script`, which runs the program. Turn on **Only list Vault script** as well to show agents just `describe_app` and the two script tools, which saves the most.

A script looks like this:

```js
const notes = await tools.search_notes({ query: "photosynthesis" });
const read = await Promise.all(notes.slice(0, 3).map((note) => tools.read_note({ id: note.id })));
return read.map((note) => ({ title: note.title, words: note.body.split(/\s+/).length }));
```

Scripts run in a sandbox with no network, files or Node.js APIs, for at most 30 seconds. They reach your vault only through the same tools, so **Read only** and each area's switch still apply: a change that isn't allowed comes back as `{ error }` instead of being made.
