better-vault works with five providers. You bring the key or the local server; better-vault never resells access or locks you to one vendor. Pick the provider and model for each question in the prompt bar.

| Provider            | Needs                         | Web mode | Pictures (Infographic)      |
| ------------------- | ----------------------------- | -------- | --------------------------- |
| **OpenAI**          | API key                       | Yes      | Yes (GPT Image models)      |
| **Anthropic**       | API key                       | Yes      | No                          |
| **Google (Gemini)** | API key                       | Yes      | Yes (Gemini image models)   |
| **Ollama**          | Ollama running on your machine | No       | No                          |
| **LM Studio**       | LM Studio's local server      | No       | No                          |

## Add an API key

1. Get a key from the provider's console: [OpenAI](https://platform.openai.com/api-keys), [Anthropic](https://console.anthropic.com/settings/keys) or [Google AI Studio](https://aistudio.google.com/apikey).
2. In better-vault, open **Settings → AI providers**, choose the provider and paste the key.
3. The model list is loaded from the provider with your key, so new models appear without an update.

Keys are stored in your browser and sent only with the request that needs them. See [Privacy](/docs/privacy).

## Use a local model (Ollama or LM Studio)

1. Install [Ollama](https://ollama.com) or [LM Studio](https://lmstudio.ai) and download a model, for example `ollama pull llama3.2`.
2. Run better-vault on the same machine (see [Get started](/docs/quickstart#install-and-run)).
3. In **Settings → AI providers**, enable Ollama (`http://localhost:11434`) or LM Studio (`http://localhost:1234`).
4. Pick the model in the prompt bar.

Local models keep your sources on your computer from start to finish. Web mode is not available with them, because it relies on a provider's built-in search.

## Which model should I use?

- For **chat and reports**, any recent large model works; larger models follow citations more closely.
- For **Studio tools** that return structured data (quizzes, flashcards, Anatomy), use a model that is good at following JSON schemas. Small local models may need a retry.
- For **infographics**, choose an image model in the tool's dialog. Its key is sent with that request only.
